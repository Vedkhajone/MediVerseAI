# 🤖 AGENTS.md — AI Agent Guidelines for MediVerse AI

Welcome, AI Coding Agent! This document provides the critical project context, architecture rules, conventions, and status updates needed to work effectively on **MediVerse AI**. Please read and follow these rules strictly.

## 1. Project Purpose & Context
**MediVerse AI** is an AI-powered full-stack healthcare management platform designed to streamline clinical workflows, patient management, medical records, and medical image/prediction analysis. 

---

## 2. Technical Stack & Architecture
The project maintains a strict separation between frontend and backend.

```
┌──────────────────────────────────────────┐
│               React UI                   │ (TanStack Start / TS)
└────────────────────┬─────────────────────┘
                     │ HTTP / JSON
┌────────────────────▼─────────────────────┐
│             FastAPI Backend              │ (Python 3.10+)
└────────────────────┬─────────────────────┘
                     │ SQLAlchemy ORM
┌────────────────────▼─────────────────────┐
│          PostgreSQL Database             │ (Supabase or custom PG)
└──────────────────────────────────────────┘
```

### Frontend
- **Framework:** React 19, TypeScript, [TanStack Start](https://tanstack.com/router/v1/docs/start/overview) (file-based routing on Vite/Nitro).
- **Styling:** Tailwind CSS, Shadcn UI components.
- **Data Access:** React Query (`@tanstack/react-query`) for cache/server state.
- **API Client:** Currently uses a stub client at `frontend/src/integrations/supabase/client.ts` that returns empty states. To connect the UI to a real backend, queries must be pointed to an API client or real Supabase client.

### Backend
- **Framework:** Python, FastAPI.
- **ORM:** SQLAlchemy (defined in [database.py](file:///c:/MediVerseAI/backend/app/database/database.py)).
- **Validation:** Pydantic v2 schemas.
- **Database:** PostgreSQL.

### AI / ML
- **Prediction:** Scikit-learn, Pandas, NumPy for tabular disease predictions (Diabetes, Heart, Parkinson's).
- **Imaging:** PyTorch / OpenCV (planned) for Brain MRI / Tumor Analysis.

## 3. Important Directories & Files

- `frontend/src/routes/` — File-based routes for TanStack Router (Layouts, Patient/Doctor/Admin views).
- `frontend/src/components/ui/` — Shadcn UI components.
- `frontend/src/integrations/supabase/client.ts` — The single entry point for frontend data queries.
- `backend/app/main.py` — FastAPI application entry point.
- `backend/app/routers/` — Endpoint definitions (e.g., patient routers).
- `backend/app/schemas/` — Pydantic schemas for request/response validation.
- `docs/` — Project architecture, database schema, API contracts, and dev logs.

## 5. Coding & Architecture Rules

> [!IMPORTANT]
> **CRITICAL AGENT PRINCIPLES:**
> 1. **Inspect Existing Code First:** Always read the file and surrounding files before modifying them.
> 2. **Prefer Focused Changes:** Keep PRs/edits small and specific. Avoid sweeping refactors.
> 3. **Separate Concerns:** Keep database/business logic out of frontend components. Keep business logic out of FastAPI route handlers by using a Service Layer.
> 4. **No Placeholders:** Write complete code, mock data, or use the image generator. Do not insert "TODO: implement this" unless it's a minor detail.
> 5. **Validation:** Always use Pydantic schemas for API request/response validation.
> 6. **SQLAlchemy Models:** Use SQLAlchemy models for database persistence. Do not write raw SQL queries in routers.
> 7. **Do Not Invent APIs:** Follow the existing Supabase schema and REST contracts in [docs/API.md](file:///c:/MediVerseAI/docs/API.md).

---

## 6. Git & Security Conventions
- **Secrets:** Never expose database URLs, JWT keys, or API tokens in code.
- **Env Files:** Never commit `.env` files. Ensure they are added to `.gitignore`.
- **Commit History:** If working on a Lovable-synced branch, **do not force-push, squash, or rebase published history**. It will break synchronization with Lovable.

---

## 7. Files That Should NOT Be Modified Casually
- `frontend/src/routeTree.gen.ts` — Auto-generated by TanStack Router. Run build/dev to update it.
- `frontend/vite.config.ts` — Configured with `@lovable.dev/vite-tanstack-config` to build Vite and Nitro entries safely.
- `frontend/src/integrations/supabase/client.ts` — Central data connector. Avoid editing unless wiring up real endpoints.
